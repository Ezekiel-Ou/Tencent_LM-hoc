# v3.2 空间坐标与距离量盘点

日期：2026-05-22

## 1. 结论摘要

当前 `agent_diy` 中同时存在三类空间量：

- raw 坐标：官方环境原始 `x/z` 坐标，主要来自 `collider.location` 或 `location`。
- projected 坐标：代码将 raw 坐标按己方视角镜像后，旋转成 `(lane, width)`。
- 距离阈值：部分基于 projected 欧氏距离，部分基于 raw 欧氏距离。

主要问题不是距离阈值需要整体乘缩放系数，而是锚点常量存在坐标系混用风险。修改前，`SELF_TOWER_ANCHOR=(-13000, 0)`、`SELF_CAKE_ANCHOR=(-15000, 0)` 在代码中被当作 projected `(lane,width)` 使用，但它们更像 raw 对角线坐标近似值。如果己方塔 raw 约为 `(-13000,-13000)`，则 projected lane 约为 `-18385`；如果己方血包 raw 为 `(-15220,-15120)`，则 projected lane 约为 `-21454`。旧锚点分别偏约 `5385` 和 `6454`。

2026-05-22 已将 `agent_diy` 中血包、外塔和基地锚点更新为 projected 坐标；血包由于两侧实际点位不完全对称，使用 camp-aware anchor。

## 2. 坐标系定义

| 项 | 代码位置 | 当前定义 | 语义 |
| --- | --- | --- | --- |
| raw location | `feature_process.py:_location_obj`、`reward_process.py:_entity_pos/_loc`、`agent.py:_own_raw_location` | 优先读取 `collider.location`，否则读取 `location` | 官方环境原始 `(x,z)` |
| 己方视角镜像 | `feature_process.py:_project_location`、`agent.py:_project_own_perspective`、`reward_process.py:_project_for_target_sort` | camp2 时 `x,z = -x,-z` | 将红方视角统一转成蓝方视角 |
| lane | 同上 | `(x + z) / sqrt(2)` | 沿主对角线推进轴 |
| width | 同上 | `(x - z) / sqrt(2)` | 垂直主路的横向轴 |
| 反投影 | `agent.py:_unproject_own_perspective` | `x=(lane+width)/sqrt(2)`，`z=(lane-width)/sqrt(2)` | force-home 等规则目标从 projected 转回 raw 动作用 |

说明：这里的 projected 指 raw `(x,z)` 经过己方视角镜像和坐标旋转后的 `(lane,width)`。它不是简单除以 2 的近似，而是除以 `sqrt(2)` 的正交旋转；这种变换保持欧氏距离不变。

## 3. 已知真实/近似点位换算

使用公式：

```python
lane = (x + z) / sqrt(2)
width = (x - z) / sqrt(2)
```

## 9. 高风险项

### 9.1 血包 anchor

血包特征、血包归属、血包消失后的 attempt 记录和 force-home 的 cake gate 都依赖 `SELF_CAKE_ANCHOR/ENEMY_CAKE_ANCHOR`。当前锚点如果按 projected 坐标理解，偏差约 `6450`，会导致：

- 血包距离特征失真。
- `hero_dist <= 3500` 的 cake attempt 判断可能漏记。
- fallback 到 `SELF_CAKE_ANCHOR` 时，吃血包冷却/force-home 状态可能误判。

### 9.2 塔 anchor

塔对象存在时，距离多使用运行时 `npc_states` 的真实位置；但选塔、塔 anchor 特征和 fallback 会用 `SELF_TOWER_ANCHOR/ENEMY_TOWER_ANCHOR`。若 raw 塔约 `(-13000,-13000)`，当前 projected 锚点偏约 `5385`。

### 9.3 base anchor 与全局 lane 范围

如果出生点/泉水 raw 约 `(-40000,-40000)`，projected lane 约 `-56568`，当前 `SELF_BASE_ANCHOR=(-40000,0)` 和 `GLOBAL_LANE_HALF=45000` 都会让基地附近表示偏粗或被 clip。

### 9.4 血包距离特征

当前血包 6 维特征中的两项距离语义已经调整为：

- 第 2 维：我方到血包局部距离，`clip(self_raw_dist / 12000, 0, 1)`，用于贴近和拾取。
- 第 3 维：我方到血包中远距离，`sqrt(clip(self_raw_dist / GLOBAL_LANE_HALF, 0, 1))`，用于 12000 外继续区分远近。
- 第 5 维：敌方英雄到血包局部距离，`clip(enemy_raw_dist / 12000, 0, 1)`，用于判断敌方是否也贴近该血包。

原 `contest_flag` 已被替换，不再直接输出“我方是否比敌方更接近血包”的布尔值。

## 10. 后续修改讨论入口

建议后续逐项讨论：

1. 是否将所有地图锚点改成 raw 常量，并通过统一 helper 生成己方视角 projected anchor。
2. 是否按真实塔/血包 raw 点位重算 `SELF/ENEMY_TOWER_ANCHOR` 与 `SELF/ENEMY_CAKE_ANCHOR`。
3. 是否把 `GLOBAL_LANE_HALF` 从 `45000` 调整到覆盖基地 projected lane 的范围。
4. 是否在不改变 feature 维度的情况下，替换血包距离特征为更局部的尺度或布尔分桶。
5. 如果新增血包特征维度，如何处理旧 checkpoint 兼容和重新训练。
