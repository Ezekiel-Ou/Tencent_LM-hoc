# 鲁班 1 技能与狄仁杰 3 技能调试日志分析

## 背景

本报告基于当前 `agent_diy` 中新增的两类调试日志：

- `LUBAN_SKILL1_DEBUG`
- `DIRENJIE_SKILL3_DEBUG`

目标是解释：

1. 鲁班 1 技能为什么没有出现 `"reason": "applied"`。
2. 狄仁杰 3 技能当前 mask 是否有效，以及还残留什么风险。
3. 下一步代码修正方案。

## 日志检索字段

建议在 Aisrv 日志中优先搜索以下字段：

- `LUBAN_SKILL1_DEBUG`
- `DIRENJIE_SKILL3_DEBUG`
- `"reason": "aim_not_legal"`
- `"reason": "out_of_range"`
- `"reason": "applied"`
- `"reason": "masked_to_enemy_hero"`
- `"reason": "enemy_hero_target_not_legal"`
- `"reason": "final_action"`

## 鲁班 1 技能日志结论

当前日志中没有发现 `LUBAN_SKILL1_DEBUG` 的 `"reason": "applied"`。主要出现的是：

- `"reason": "aim_not_legal"`
- `"reason": "out_of_range"`

其中最关键的重复模式是：

```text
"sub_action_mask_4": [1, 0, 0, 1, 1, 1]
"skill1_target_legal": [0, 0, 1, 0, 0, 0, 0, 0, 0]
```

这说明鲁班 1 技能在当前官方 action 协议下：

1. button 4 的 target 子动作是启用的，不是被忽略字段。
2. 环境给出的合法目标不是 `enemy_hero` 的 index 1。
3. 日志中稳定合法的是 target index 2。

而当前代码的鲁班 1 技能辅助瞄准逻辑把目标强行设为敌方英雄：

```text
target = 1
```

因此 `_is_luban_skill1_aim_legal()` 会检查 target 1 是否合法。由于日志里的 `skill1_target_legal` 通常是 `[0, 0, 1, 0, 0, 0, 0, 0, 0]`，target 1 不合法，最终进入：

```text
"reason": "aim_not_legal"
```

这就是没有 `"reason": "applied"` 的直接原因。

## 对官方协议的理解修正

之前把鲁班 1 技能理解成“朝敌方英雄目标释放”是不准确的。

从日志和 `sub_action_mask_4` 看，鲁班 1 技能更接近“以自身或指定锚点为释放目标，然后用 x/z 方向参数决定落点或方向”的技能。也就是说，目标位很可能应该使用当前环境允许的 target index 2，而不是敌方英雄 target index 1。

这也解释了为什么即使敌方没有走位，依然不能稳定命中：当前问题不是敌方移动预测不足，而是动作参数层面不合法，技能辅助逻辑在合法性检查阶段就被拦下了。

## `out_of_range` 的次要问题

日志中也有一些 `"reason": "out_of_range"`，包括敌方可见但距离大于当前代码阈值的情况。

当前代码里有硬编码距离门槛：

```text
LUBAN_SKILL1_AIM_RANGE = 8800
```

这个阈值可能偏保守，但它不是没有 `applied` 的第一主因。第一主因仍是 target index 选错。修正 target 后，再决定是否放宽距离门槛或完全信任官方 `legal_action`。

## 鲁班 1 技能修正方案

建议分两步改，先做低风险修正，再做方向精修。

### 第一步：修正 target 语义

把鲁班 1 技能辅助瞄准的目标从敌方英雄 index 1 改为日志显示合法的 index 2：

```text
LUBAN_SKILL1_AIM_TARGET = 2
```

合法性检查同步改为检查 target 2：

```text
skill1_target_legal[2] == 1
```

这一步的预期结果：

- `LUBAN_SKILL1_DEBUG` 开始出现 `"reason": "applied"`。
- `action_after` 不再为 `null`。
- 鲁班 1 技能实际有机会被辅助逻辑改写为合法动作。

### 第二步：修正 x/z 瞄准方向

当前辅助逻辑使用固定中心值：

```text
skill_x = 8
skill_z = 8
```

这对需要方向或落点的技能不足。建议改为：

1. 使用 `enemy_pos - main_pos` 计算敌方相对方向。
2. 将相对方向映射到 16 桶动作空间。
3. 若首选桶不合法，则在合法桶里选择距离首选桶最近的值。
4. target 使用 index 2。

初版可以先沿用已有的三档方向估计以降低风险；如果命中率仍不足，再升级为 16 向角度映射。

## 推荐代码行为

鲁班 1 技能辅助逻辑建议变成：

1. 仅在 `main_hero_id == 112` 且模型选择 button 4 时介入。
2. 敌方英雄不可见时不介入。
3. 如果官方 mask 显示 button 4、skill_x、skill_z、target 2 均合法，则改写 action。
4. 否则只打印 debug，不强行改写。
5. 距离判断优先弱化，更多信任官方 `legal_action`。

## 狄仁杰 3 技能日志结论

狄仁杰 3 技能日志中已经出现：

```text
"reason": "masked_to_enemy_hero"
"skill3_target_legal_after": [0, 1, 0, 0, 0, 0, 0, 0, 0]
```

这说明当敌方英雄 target index 1 合法时，当前 mask 能正确把 3 技能目标限制到敌方英雄。

但也存在大量：

```text
"reason": "enemy_hero_target_not_legal"
```

这类日志常伴随：

```text
"enemy_visible": false
"enemy_pos": [100000.0, 100000.0]
```

当前逻辑在敌方英雄 target 不合法时没有禁用 button 6，只是放弃改写 target row。这样模型仍可能选择 button 6，并落到非敌方英雄目标或无效目标上。

## 狄仁杰 3 技能修正方案

建议下一步把逻辑收紧为：

1. 如果 button 6 不合法，不处理。
2. 如果敌方英雄 target index 1 合法，继续把 target row mask 成 `[0, 1, 0, 0, 0, 0, 0, 0, 0]`。
3. 如果敌方英雄 target index 1 不合法，直接把 button 6 置为非法，避免大招打到小兵、自身或空气目标。
4. 保留“释放后 30 帧没有命中敌方英雄则小额负奖”的 miss penalty。

## 结论

鲁班 1 技能当前没有 `"reason": "applied"` 的信息已经足够定位问题：不是敌方走位导致命中失败，而是辅助瞄准动作本身不符合官方合法动作 mask。核心错误是把鲁班 1 技能 target 当成了敌方英雄 index 1，而日志显示当前合法 target 是 index 2。

优先修改鲁班 1 技能 target 到 index 2，并按敌我相对位置计算 x/z。完成后再用 `LUBAN_SKILL1_DEBUG` 验证是否出现 `"reason": "applied"`，再观察实际命中率。
