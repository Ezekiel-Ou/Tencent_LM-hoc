## 1. 规则生效阶段与血线（HP threshold）

### 1.1 生效阶段（重要变更）

**v3.0 只在 `frame < 6000` 期间启用强制回家规则；`frame ≥ 6000` 完全不再触发本规则**，所有撤退/回家决策交还给策略自身（恢复技能、吃神符、召唤师技能、走位等都由网络学习）。

设计意图：
- 中后期（6000 帧≈200 秒后）英雄已成型，装备/吸血/技能组合多样，物理走回泉水的"兜底"价值急剧下降，规则反而会盖掉策略本该选择的反打/带线/换塔等高价值动作。
- 6000 帧之前是新手期，鲁班/狄仁杰装备未起来，被一发技能秒杀风险高，需要规则在"被追杀且无主动恢复手段"时强制走回避免送死。
- 6000 是设计取值（比环境的 `CANNON_FRAME = 6254` 略早），目的是在大炮兵抵达之前的小波动期就退出规则，避免规则与大炮兵带来的战局节奏冲突。

### 1.2 血线（仅前期生效）

| 阶段 | 触发回家血线 HP_TRIGGER | 切换回程血线 HP_RECOVERED |
| --- | --- | --- |
| 前期（frame < 6000） | < **0.20** | ≥ **0.80** |
| ≥ 6000 | —— 规则不触发 —— | —— |

设计意图：
- 前期 20% 一旦被一发技能就死，作为"最后兜底"更合理；高于这条线时让策略自己选择继续干扰、用恢复、吃血包等。
- 回程门槛从 90% 降到 80%：泉水回血曲线在 70%+ 后边际收益迅速降低，强行等到 90% 浪费 5–8 秒线上经验/经济。

新增/修改配置项（`conf.py: GameConfig` 命名空间）：

```python
FORCE_HOME_PHASE_END_FRAME        = 6000     # 新增：本帧及之后规则完全不触发
FORCE_HOME_HP_TRIGGER_PRE_CANNON  = 0.20     # 原 0.35
FORCE_HOME_HP_RECOVERED           = 0.80     # 原 0.90
# 移除：FORCE_HOME_HP_TRIGGER（原 post-cannon 阈值，v3.0 不再使用）
```

> 注：v2.x 的 `FORCE_HOME_HP_TRIGGER`（post-cannon 0.20）在 v3.0 中被弃用，因为 ≥ 6000 帧规则整体不触发；保留常量名仅为兼容旧代码引用，建议在实施阶段清理。

## 2. 敌方英雄安全距离

```python
FORCE_HOME_ENEMY_SAFE_RANGE = 10000.0   # 原 8800.0
```

约束：触发回家时必须 **敌方英雄不可见** 或 **己我投影距离 > 10000**，否则不触发（避免背身被追杀）。

理由：8800 在 1v1 中已接近鲁班 1 技能 / 狄仁杰 3 技能可触发的距离，转身就走极易吃到点控。10000 给出更稳的反应窗口；且 v3.0 触发血线下移，触发频率下降，可以承担更严苛的安全门槛。

`_enemy_invisible_or_far` 不需要结构改动，只需调用上述常量。

## 3. 防御塔血量门控

```python
FORCE_HOME_TOWER_HP_MIN = 0.40   # 原 0.35
```

己方一塔 HP ≤ 40% 时**不触发**强制回家。原因：塔血极低时塔的火力威慑已经无效，回去并不安全，反而应让策略选择「继续干扰 / 死亡换塔」。门控由 35% 上调到 40% 后，更早进入策略自主模式。

## 3.5 兵线门控（v3.0 新增硬规则）

> 兵线情况原本在第 6 节的"复杂规则占位"中。v3.0 将其中**两条最关键的判定提升为硬规则**，必须满足才能触发强制回家。剩余的复杂兵线判定（己方塔承伤率、推塔时机等）仍留在第 6 节。

### 3.5.1 己方塔下不能有敌方小兵

**条件**：触发回家时，己方一塔的攻击范围内**不能有敌方小兵存在**。

理由：
- 一旦走开离塔，塔会切目标到剩下的小兵继续清，但小兵会持续推塔；
- 更关键的是：留在塔下清完这波兵性价比高于"现在走"——既能拿经验/经济，也避免塔被白嫖。
- 与第 3 节"塔血 > 40%"形成互补门控：塔血够（值得守）+ 没有敌方兵（守起来不费血）→ 可以放心走。

判定方法：
- 沿用 `_find_my_hero_and_tower` 拿到 `main_tower`，然后在 `npc_states` 中筛选 **敌方阵营** + **小兵子类型** + **在 `main_tower` 攻击半径内**的单位；
- 攻击半径优先使用 `main_tower.attack_range`（如观测可得），否则用 `TOWER_ATTACK_RANGE_FALLBACK = 8800`（已有常量）。
- 数量 > 0 → 不触发回家；= 0 → 该项门控通过。

```python
FORCE_HOME_TOWER_AREA_ENEMY_MINIONS_MAX = 0   # 新增：塔下允许的最大敌方小兵数（必须为 0）
```

### 3.5.2 敌方英雄死亡时的额外兵线门控

**条件**：当敌方英雄处于死亡状态（`enemy_hero.dead_cnt` 增加 或 `hp <= 0`）时，**必须**先把 lane∈[-13000, 13000] 区间内（己方投影坐标系）的**所有敌方小兵清理完毕**，才能触发回家。

> lane 区间说明：
> - lane = -13000 ≈ 己方一塔线附近（参考 `SELF_TOWER_ANCHOR = (-13000, 0)` 的 raw 坐标，注意需要确认投影后是否在此数量级；实现时以投影后实际数值为准，命名仍用 -13000 / 13000 作为常量表达）；
> - lane = +13000 ≈ 敌方一塔线附近；
> - 整个区间覆盖"两塔之间的整条对线"。

理由：
- 敌方英雄死亡 = 我方有**完整的真空时间窗口**（30~50 秒，取决于复活 CD）；
- 此时撤退是浪费——应抓紧推线/拿经济。线上有任何敌方小兵没清就回家，等于把这波兵塞给敌方塔吃，并且回家后兵线会被推回我方塔下，葬送优势。
- 把"清完小兵"作为前置条件，强制策略在敌方英雄死亡时打满兵线收益再考虑回家。

判定方法：
- 检查 `enemy_hero is None` 或 `enemy_hero.dead_cnt` 比上一次记录的更高 或 `enemy_hero.hp <= 0`；
- 若敌方英雄死亡，扫描 `npc_states` 中所有敌方阵营小兵：
  ```
  enemy_minion_in_range = any(
      minion.camp == enemy_camp
      and minion.sub_type in ENEMY_MINION_SUB_TYPES
      and -13000 <= lane_of(minion) <= 13000
      for minion in npc_states
  )
  ```
  存在任意一只 → 不触发；全部清理完 → 该项门控通过。
- 实施时 `lane_of(minion)` 使用 `_project_own_perspective(minion)[0]`，仍是**己方投影坐标系**，红蓝方对称由现有翻转机制保证（**不要按阵营再加符号**）。

```python
FORCE_HOME_ENEMY_DEAD_LANE_LO = -13000.0   # 新增：敌方死亡时需清兵的 lane 下界（己方塔线）
FORCE_HOME_ENEMY_DEAD_LANE_HI =  13000.0   # 新增：敌方死亡时需清兵的 lane 上界（敌方塔线）
```

> 实现细节提示：敌方英雄死亡的判定需要在 agent 状态中跟踪 `prev_enemy_dead_cnt`，类似现有的 `prev_dead_cnt`（main_hero）。新增 `self.prev_enemy_dead_cnt = 0`，每帧更新。

### 3.5.3 与 3.5.1 的关系

- 3.5.1（己方塔下无敌方兵）**始终**作为前置条件检查；
- 3.5.2（敌方英雄死亡时清线）**只在敌方英雄死亡期间**叠加；
- 两条都通过 + 第 1~3 节其他条件都通过 → 才进入触发判定的最后一步（HP 血线检查）。

## 4. 血包（神符）刷新与撤退途中的"提前退出/暂缓触发"

### 4.1 血包刷新时间是否可知？—— **可以精确预测**

- 环境常量 `CAKE_RESPAWN_SECONDS = 75`，1 步 6 帧、1 帧 ≈ 33ms → 75s ≈ **2250 frames**。
- 现有逻辑（`agent.py:1146 _update_own_cake_state`）已在维护：
  - `own_cake_exists`：本帧己方半场是否存在血包；
  - `own_cake_seen_once`：本局是否曾经见过血包（用于首次刷新判定）；
  - `last_own_cake_disappear_frame`：上一次消失（被吃 / 过期）的帧；
  - `next_own_cake_frame = last_own_cake_disappear_frame + 2250`：下一次刷新的预测帧。
- 因此「距离下次刷新还剩 ΔF 帧」可以直接算：`ΔF = max(0, next_own_cake_frame - frame_no)`。
- **首次刷新**（开局第一颗血包）的时间由环境本身决定，没法由 75s 公式推导，只能等观测到 `cakes` 列表中第一次出现己方半场血包（`own_cake_seen_once = True`）后才有锚点。在此之前 v3.0 把它视作"不可预测，按"未来某帧"处理"，不基于它做提前退出。

### 4.2 lane 分段（己方投影坐标系）

> 关键提醒：这里的 `lane` 是 `_project_own_perspective` 之后的坐标，**已经做过红蓝方镜像翻转**（蓝方天然处于左下角；红方在 `_own_raw_location` / `_project_own_perspective` 中通过 `x, z = -x, -z` 翻转到同一视角）。所有阈值都是「己方视角下、越负越靠近泉水」的语义。
>
> 现有锚点参考（投影后近似值）：
> - 己方一塔线 `FORCE_HOME_RETURN_EXIT_LANE = -15000`（这是 v2.x 已用的 lane 阈值）。
> - 越往负方向越深入己方半场。-20000 介于一塔与泉水之间，属于「己方腹地」。

将撤退路径切成两段，行为不同：

#### A. 浅层撤退区 `lane > -20000`（接近兵线/一塔，还能选别的）

在该区域内的每一帧检查：

1. **血包提前退出**：如果当前观测到己方半场存在血包（`own_cake_exists == True`），**立即退出 force-home 规则**（清空 phase，把控制权交还给策略）。策略本身有 `cake_pickup` 奖励项（`conf.py: rewards.cake_pickup = 1.0`），它会主动吃。
2. **预测刷新提前等位**（可选优化）：如果 `own_cake_exists == False` 但 `next_own_cake_frame` 已知，且 `next_own_cake_frame - frame_no <= LANE_CAKE_WAIT_FRAMES`（建议 60 frames ≈ 2s），可以视为"即将刷新"，原地或就近停下而不是继续撤退。**初版可不做**，先验证基本版。
3. **恢复手段可用则不触发回家**：在触发判定阶段（`_should_start_force_home`），若以下任一条件成立则 **不触发**：
   - 装备恢复技能可用（slot 4：`_is_recover_skill_available(main_hero)` 已存在）；
   - 召唤师技能为治疗术 `80102` 且 CD 完毕（`legal_action` 中 button=8 合法）；
   - 已经处于「正在回血」窗口（见 4.3）。
4. **吸血状态**（属第 6 节复杂规则，初版可先跳过）：装备/Buff 提供高吸血时，触发线再下调。

#### B. 深层撤退区 `lane ≤ -20000`（已经走到一塔后方，接近泉水）

- **不再检测血包 / 恢复**：按 v2.x 既有逻辑沿路径继续走到泉水，直到 HP ≥ 0.80 切回 return 阶段。
- 理由：到这里已经走过大半路程，掉头去吃血包反而更绕；且泉水回血极快，再几秒就满血。

```python
FORCE_HOME_DEEP_LANE = -20000.0   # 新增：低于此 lane 视为深层撤退，不再做提前退出检查
LANE_CAKE_WAIT_FRAMES = 60        # 新增（可选）：预判刷新窗口
```

### 4.3 "刚回过血" 冷却窗口 —— 防止反复触发

行为：每当**用完恢复技能** 或 **吃到血包** 后，开启一个 4 秒（**120 frames**）的冷却窗口，在窗口内**不触发**强制回家。

判定细节：
- "用完恢复技能"复用现有 `_detect_recover_low_hp`（`feature/reward_process.py:1232`）的窗口设计：观察到 `RECOVER_START_BUFF_ID = 10000` 起飞 → 进入 pending → `RECOVER_CONFIRM_FRAMES = 15` 内 HP 提升 ≥ `RECOVER_HP_GAIN_THRESHOLD = 200` 判定为成功；成功的那一帧记 `last_recover_success_frame = frame_no`。
- "吃到血包"由 `_update_own_cake_state` 在 `own_cake_exists True → False` 的过渡帧上、且该过渡发生在己方英雄附近（投影距离 < e.g. 1500）时记 `last_cake_eaten_frame = frame_no`。需要新增这个判定（现在只记 `last_own_cake_disappear_frame`，没区分是被吃还是别的原因消失）。
- 冷却窗口：`COOLDOWN = max(last_recover_success_frame, last_cake_eaten_frame) + 120` 之前**不触发回家**。
- **回血被打断的逃生口**：若在冷却窗口内 HP **反而下降** 或仍低于 v3.0 触发血线（即回血被打断 / 被一波连招带回低血量），允许提前退出冷却、再次触发回家。判定方法：
  ```
  if (cooldown_active) and (hp_rate < FORCE_HOME_HP_TRIGGER_current_phase):
      cooldown_active = False   # 立即解除冷却，允许再次触发
  ```
- 冷却窗口自然结束（超过 4 秒）后，按正常规则评估：HP 仍低 → 再触发；HP 已高 → 不触发。

新增配置：
```python
FORCE_HOME_RECOVER_COOLDOWN_FRAMES = 120   # 4 秒（30 fps）
CAKE_PICKUP_PROXIMITY = 1500.0             # 判定"是我吃的"的最大投影距离
```

新增 agent 状态字段：
```python
self.last_recover_success_frame = -10000
self.last_cake_eaten_frame      = -10000
```

## 5. 触发与撤退状态机（v3.0 改后）

伪代码（实际实现时以 `_maybe_force_home` 内现有结构为基础修改）：

```
on every decision frame:
    更新 own_cake 状态、last_recover_success_frame、last_cake_eaten_frame、prev_enemy_dead_cnt
    解析 HP_TRIGGER / HP_RECOVERED (仅前期值；frame >= 6000 直接 return)

    # 全局门控：6000 帧之后规则完全不触发
    if frame_no >= FORCE_HOME_PHASE_END_FRAME (6000):
        if force_home_phase is not None:
            clear_phase     # 已在撤退中也要清掉，避免越界
        return action

    if dead 或 respawn(dead_cnt 变化):
        clear phase; return action

    if force_home_phase is None:
        # 触发判定（所有条件 AND，任何一条失败都不触发）
        if not own_cake_unavailable:                  return action     # 半场有血包 → 让策略自己去吃
        if recover_skill_available(main_hero):        return action     # 恢复技能可用 → 让策略自己用
        if heal_summoner_ready(observation):          return action     # 召唤师治疗术可用 → 同上
        if in_recover_cooldown(frame_no):             return action     # 4s 冷却内 → 不触发
        if not enemy_invisible_or_far(...,10000):     return action     # 敌人太近 → 不触发
        if not tower_hp_above(main_tower, 0.40):      return action     # 塔血<40% → 不触发
        if enemy_minions_in_own_tower_range() > 0:    return action     # § 3.5.1 塔下有敌方兵
        if enemy_hero_dead and any_enemy_minion_in_lane(-13000, 13000):
                                                       return action     # § 3.5.2 敌方死亡但兵未清
        if hp_rate >= HP_TRIGGER_PRE_CANNON (0.20):   return action
        → 进入 phase = "retreat_spring"

    if phase == "retreat_spring":
        # 浅层撤退：可被血包/恢复"打断"
        if lane(main_hero) > FORCE_HOME_DEEP_LANE:    # 即 lane > -20000
            if own_cake_exists:                  clear_phase; return action
            if recover_skill_available(main_hero): clear_phase; return action
        if hp_rate >= HP_RECOVERED(0.80):
            phase = "return"
        else:
            return force_walk_to(retreat_target)

    if phase == "return":
        # 沿路径回到一塔线，过 -15000 即解除
        if hp_rate < HP_TRIGGER_PRE_CANNON (0.20):
            phase = "retreat_spring"; return ...
        if lane(main_hero) >= FORCE_HOME_RETURN_EXIT_LANE:  # -15000
            clear_phase; return action
        return force_walk_to(return_target)
```

注意：
- "回血被打断" 的快速重触发由 `in_recover_cooldown` 内置的 `hp_rate < HP_TRIGGER` 早返机制处理（见 4.3）。
- 红蓝方对称由 `_project_own_perspective` 已有的 `force_home_camp == 2 → 翻转坐标` 保证。lane 阈值都用己方视角的同一套数值，**不要按阵营再加符号**（这包括 § 3.5.2 的 `-13000 / 13000`）。
- `frame >= 6000` 的提前 return **优先级最高**，会强制清掉任何正在进行的撤退/回程 phase；这意味着即使 5990 帧刚触发的撤退，几帧后也会被 6000 切断，把控制权交回策略。可以接受——刚触发就被切断说明 HP 已经不算危急，让策略自己处理。

## 6. 复杂规则（占位，下一步细化）

下列三块当前仍是概念占位，本版只声明字段与判定输入，**v3.0 第一阶段先不接入触发判定**，等行为验证稳定后再加权进规则。

### 6.1 吸血 / 自愈状态

- 输入：
  - 狂暴 80110 召唤师 buff 是否生效（`hero.buff_state` 或 `buff_ids` 中含狂暴效果 id）；
  - 装备中是否含吸血装（"血魔之怒"等，可通过 `equipment_states` 查询，需补字段映射）；
  - 当前对兵线/英雄普攻命中率（可从 `hurt_to_*` 增量近似估计）。
- 决策影响：
  - 若处于高吸血窗口，**触发血线再下调 5%**（前期 15%），或在 lane > -20000 区域直接「让策略选择继续打钱回血」。

### 6.2 敌方英雄状态

- 输入：
  - 敌方 HP、MP（即便不可见也能从最近一次可见帧推测）；
  - 敌方关键技能 CD：1/2/3 技能 + 召唤师；
  - 敌方移动方向（最近 N 帧位移向量 vs 我方位置）—— 用于判断"在追击"还是"在回家"；
  - 敌方是否处于控制 / 减速 / 沉默等不利状态。
- 决策影响：
  - 敌方关键控制技能（鲁班 2 击退、狄仁杰 3 眩晕）**正在冷却** → 安全距离阈值从 10000 放宽到 8500；
  - 敌方正在朝我方向移动且距离 < 12000 → 安全距离从 10000 提到 12000，并优先选择"塔下停留"而非"走回泉水"；
  - 敌方血量比我方更低（kill 窗口）→ **不**触发回家（让策略尝试反打），但仍保留死亡兜底（HP < 5%）。

### 6.3 兵线情况（剩余项）

> § 3.5 已把"己方塔下无敌方兵"与"敌方英雄死亡时清线"提升为硬规则。本节只列**未提升**的复杂判定，留待后续阶段细化。

- 输入：
  - 己方/敌方小兵在 lane 上的中位投影位置；
  - 己方一塔当前承受的伤害（最近 N 帧 tower HP 下降率）；
  - 当前兵线接近哪一方塔。
- 决策影响：
  - 兵线在敌方塔下且己方塔无威胁 → 回家性价比高（让步给"切回程时机"，把 HP_RECOVERED 降到 0.70）；
  - 兵线在己方塔下且塔正承伤 → 不触发回家，必须留下来清兵守塔（除非 HP 已经低于 5%，但 v3.0 触发血线已是 20%，这条更多是为了和未来更激进的策略层做衔接）。

## 9. 实施顺序建议（非本版本范围）

1. **阶段 A**：v3.0 的常量改动（第 1 项）+ 6000 帧硬总开关（第 2 项）+ "恢复可用则不触发"短路（第 3 项）+ 兵线硬门控（第 8、9 项）。
   - 这是 v3.0 的"最小可验证集"。跑一轮自对战观察：win_rate、死亡数、回家次数、回家分布（按 frame）、6000 帧前后行为切换是否平滑。
2. **阶段 B**：加 4 秒冷却（第 4 项）+ lane 分段（第 5、6 项）。
3. **阶段 C**：血包吃判定精化（第 7 项）。
4. **阶段 D**：复杂规则（第 10 项），逐条引入，每条单独 ablation。

每个阶段保留上一阶段的训练曲线作为对照，避免"一锅端"造成回归无法定位。

特别提示：阶段 A 的兵线门控（8、9 项）会让触发频率明显下降，可能出现"该回家时没回"的死亡 case 增多。这是预期内的——v3.0 的整体方向就是"宁可让策略多打几次，也不要规则盖掉好动作"。如果死亡率上涨幅度超出预期（> 20%），再考虑放宽 § 3.5.1 的"塔下无兵"门控为"塔下敌方兵 ≤ 1 只"。
