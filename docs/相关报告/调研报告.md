## 0. 执行摘要（TL;DR）

我把官方 baseline 完整翻了一遍，结论用一句话概括：**baseline 是一个"故意留有大量空白"的最简骨架，照搬它训不出能打的模型，但它给了我们极其清晰的发力靶点。** 当前 `agent_ppo` 的特征只有 10 维（绝悟论文是 725+ 维）、奖励只有 2 项（绝悟论文是 8 项）、声明了 LSTM 但 forward 里完全没用、声明了 target attention 也没用，value loss 还被写了两遍——这意味着任何认真做的改进都能立刻看到收益。

往届开悟冠军公开分享的关键认知是：**算法选 PPO 没有任何争议，决胜点在网络结构 / 奖励函数 / 损失函数 / Self-play 课程设计**（见 [冠军思路分享](https://zhuanlan.zhihu.com/p/654972230)）。我们要做的是把腾讯绝悟 AAAI 2020 论文（[arXiv:1912.09729](https://arxiv.org/abs/1912.09729)）和 hok_env 的开源 baseline（[GitHub](https://github.com/tencent-ailab/hok_env)）当作"标准答案"，把这套组合（多模态特征 + 注意力 + LSTM + Dual-clip PPO + 零和奖励 + Self-play 课程）一比一搬到 `agent_diy/` 里，再做平台特化的调参与课程设计。

**夺冠最短路径**：
1. **第 1 周**：把特征从 10 维拉到 ~700 维（参考绝悟分组：hero / soldier / tower / monster / global），把奖励从 2 项扩到 8 项（按官方权重表），修掉 baseline 的两个明显 bug（LSTM 没接、value loss 写两遍），加上**动作约束损失**消除"站着不动 / 乱放技能"问题 → 期望训练 6 小时左右就能稳定击败 common_ai。
2. **第 2 周**：上 Dual-clip PPO + Target Attention + LSTM 时序（FC:GRU = 3:1 混合，避免在有限算力下 LSTM 过拟合），进入有效的 self-play。
3. **第 3-4 周**：League / PFSP 课程 + 召唤师技能策略学习 + 镜像数据增强 + advantage 归一化 + **情景奖励**（让稀有但关键的对线/打塔时机被放大）→ 进入"和顶尖队伍对线"阶段。
4. **比赛末期**：精调奖励权重、做对手特化训练、用 Module Soup（多个 checkpoint 加权平均）+ best-of-N 策略上传多个互补模型。

> 第 4 章末尾新增了一个 **"4.9 实战增量：来自电子科大亚军的具体 trick"**，里面有动作约束损失、PSCN 模块、情景奖励等的可直接落地实现，强烈建议先读那一节再看路线图。

## 1. 赛题与平台的硬约束

### 1.1 任务规格（来自 `开发指南/项目简介.md`、`数据协议.md`）

- **形式**：1v1，红蓝双方各一名英雄，墨家机关道地图。
- **英雄池**：仅鲁班七号（112，物理远程射手）和狄仁杰（133，物理远程射手）——**两个英雄机制都是"普攻型射手"，这是好消息：策略空间相对收敛**，不像全英雄池那么发散。
- **召唤师技能**：10 个候选（治疗 / 疾跑 / 惩击 / 终结 / 狂暴 / 干扰 / 晕眩 / 净化 / 弱化 / 闪现），**对局开始前自主选择 1 个**。
- **胜负条件**：摧毁对方"水晶前防御塔"的一方胜，超时（20000 帧 ≈ 660 秒 ≈ 11 分钟）双方均不得分。
- **决策频率**：1 step = 6 frame ≈ 198 ms（即 ~5 Hz 的决策频率）。
- **评价**：多轮循环对战累计胜场数。

### 1.2 动作空间（关键，必须吃透）

`LABEL_SIZE_LIST = [12, 16, 16, 16, 16, 9]`，6 个独立的离散动作头：

| 序号 | 维度 | 含义 |
|----|----|----|
| 0 | 12 | button：哪个按钮（none / move / attack / skill1-3 / heal / chosen-skill / recall / skill4 / equip） |
| 1 | 16 | move_x：移动方向 X 偏移 |
| 2 | 16 | move_z：移动方向 Z 偏移 |
| 3 | 16 | skill_x：技能方向 X 偏移 |
| 4 | 16 | skill_z：技能方向 Z 偏移 |
| 5 | 9 | target：技能/普攻目标（none / 敌方英雄 / 自身 / 4 个最近小兵 / 1 个塔 / 1 个野怪） |

两层 mask：
- **legal_action**：基于游戏规则的硬约束（CD 中、地图边界等），按位与到 logits。
- **sub_action_mask**：依赖于 button 的层级 mask（如非方向技能屏蔽 skill_x/z）。这一层的实现要求 target head 的合法性必须由当前选中的 button 决定（baseline 已经实现这个 conditional：`target_legal_action_o * one_hot_button`）。

### 1.3 平台限制

- 模型保存频率上限：**2 次/分钟，单任务最多 400 次**——意味着不能每步都 dump，需要合理设 `dump_model_freq`。
- 日志限流：60 条/分钟。
- 评估时调 `agent.exploit`，输入是单帧 observation；训练时调 `agent.predict`。
- `kaiwu.json` 里可以挂最多 3 个对手模型 ID 用于评估对战。

### 1.4 自带 baseline 的能力上限

按照 NeurIPS 2022 [Honor of Kings Arena](https://arxiv.org/abs/2209.08483) 论文里的对照实验：完整版 PPO + 725 维特征 + LSTM + Dual-clip 训练 ~80 小时 Elo 才会饱和。**当前 `agent_ppo` 的特征是 10 维，理论上限远低于此**——所以就算完整跑完 baseline，也打不过认真做的对手。这给了我们巨大的优势空间。

## 4. 技术栈与方案选型

### 4.1 算法：**只用 PPO**

往届冠军的明确结论："第一届很多队伍尝试 SAC、A2C、IMPALA 各种算法，最终冠军全是 PPO；第二届所有队伍都不再纠结，统一用 PPO" ([知乎](https://zhuanlan.zhihu.com/p/654972230))。理由：
- MOBA 是稀疏奖励 + 长 horizon + 大动作空间，PPO 的截断更新机制最稳定；
- 平台框架默认 on-policy，PPO 与之契合；
- Dual-clip PPO 已经在绝悟里被证明是 MOBA 的最优解；
- 切别的算法相当于把整个采样/训练管线重写一遍，时间成本巨大。

**不要碰 SAC、Rainbow、Muzero 这类**。所有精力放在 PPO + 它的辅助 trick 上。

### 4.2 网络结构（参考绝悟原图）

目标结构（用 PyTorch 写在 `agent_diy/model/model.py`）：

```
                    ┌─── Encode ───┐
inputs              │              │
─ public_hero_feat  → MLP(256)     │
─ private_hero_feat → MLP(256)     ├─→ Concat ─→ MLP(512) ─→ LSTM(512) ─→ ┬─→ Action heads (6 个独立 head)
─ soldier_feat      → MLP+pooling  │                                       │
─ organ/tower_feat  → MLP(128)     │                                       └─→ Value head
─ global_feat       → MLP(128)     │                                       └─→ Target attention 用 LSTM 输出 query 与 unit embedding 做 dot product
                    └──────────────┘
```

要点：
1. **特征分组编码**：每组特征单独 MLP 编码到固定维度，再 concat；不要把所有特征 flat 进一个 MLP。
2. **LSTM 真的接进去**（修 baseline bug #3）：LSTM 输入是 concat 后的特征，输出作为 6 个 action head 的输入，同时也作为 value head 的输入。LSTM_TIME_STEPS=16 已经在样本组织里准备好了。
3. **Target Attention**（修 baseline bug #4）：把每个候选 target（敌方英雄、4 小兵、塔、野怪）也做 unit embedding，用 LSTM 输出的 hidden 做 query 算 attention，得分作为 target head 的 logits。绝悟原文这一项消融实验显示提升 5%+ 胜率。
4. **6 个 head 独立 logits + decoupled PPO loss**：这是绝悟的"控制依赖解耦"，每个 head 一个 PPO loss 加起来。当前 baseline 的 `is_reinforce_task_list` 已经在跑这套，结构上不用改。
5. **Critic 共享 backbone**：value head 直接接在 LSTM 输出后面（共享 + 单独 MLP）。

### 4.3 特征工程（最大投入回报点）

按绝悟 / hok_env 的 725 维拆分（[NeurIPS 2022](https://arxiv.org/abs/2209.08483)）：

| 分组 | 维度量级 | 内容 |
|----|----|----|
| `public_hero_feature` | ~150 / hero | 双方英雄的 alive、HP、HP_max、EP、level、money、kill_cnt、dead_cnt、location（含镜像）、forward、attack_range、phy/mgc atk/def、mov_spd、buff_state |
| `private_hero_feature` | ~50 / hero | 6 个技能槽（slot_type、cooldown、cooldown_max、level、usable）、equip_state（装备 ID + 数量 + active_skill cooldown）、召唤师技能 |
| `soldier_feature` | ~80 | 双方最近 4 小兵的 HP、location、attack_target、camp、距离主英雄距离 |
| `organ_feature` | ~30 | 双方水晶 + 防御塔 + 泉水塔（HP、location、is_alive） |
| `monster_feature` | ~20 | 1 个野怪的 HP、location |
| `bullet_feature` | ~30 | 飞行中的子弹/技能弹道（位置、源头、剩余距离） |
| `global_feature` | ~30 | frame_no（归一化）、kill 差、money 差、tower_hp 差、time-to-respawn、双方等级差 |

**实施要点**：
- 每个 unit 字段做标准化（HP/max_HP；金钱/上限值；位置 / 战场尺寸）；
- 视野外的敌方单位用全 0（保留 mask 位指示是否可见）；
- 镜像变换继承 baseline 的写法（红方所有 x/z 取负）；
- 角色 ID（112/133）做 one-hot 拼到全局特征；
- 召唤师技能 ID 做 one-hot 拼到全局特征——**这是让 init_config 学会的关键**。

预计扩到 600~800 维。第一版没必要追求 725，先把"敌方英雄被看见"和"自身技能 CD 被看见"补齐，胜率就会有质变。

### 4.4 奖励工程（按官方权重直接抄）

来自官方 hok_env 的默认 config（[GitHub](https://github.com/tencent-ailab/hok_env)）：

```python
REWARD_WEIGHT_DICT = {
    "tower_hp_point": 5.0,    # 塔血量比（核心目标）
    "hp_point":       2.0,    # 自身血量比
    "ep_rate":        0.75,   # 法力值比
    "last_hit":       0.5,    # 补刀
    "kill":           0.6,    # 击杀（注意：原版是 -0.6，正负取决于零和的实现习惯）
    "dead":          -1.0,    # 死亡
    "money":          0.006,  # 金币（数值大，权重要小）
    "exp":            0.006,  # 经验
    "forward":        0.01,   # 前进（保留 baseline 的实现）
}
```

并且必须用**零和**：`reward = main_camp_value - enemy_camp_value` 然后再做帧间差分（baseline 的 `reward_process.py:160-170` 已经写好了零和模板，照搬即可，只是把 reward 项扩开）。

**进阶 reward 设计（中后期）**：
- `hp_point` 用四次根号 (`hp_rate_sqrt_sqrt`) 做非线性变换，让低血量更敏感（3v3 baseline 的做法）；
- `attack_hero`：每帧对敌方英雄造成的伤害（不是击杀，而是输出量），权重 0.001-0.01；
- `time_decay`：按 `0.6^(frame_no/4500)` 衰减，鼓励早结束局；
- `no_op_penalty`：连续多帧 button=None 的负奖励，避免 baseline 提到的"站着不动"问题（参考[冠军分享](https://zhuanlan.zhihu.com/p/654972230)）。

### 4.5 算法关键超参（按绝悟论文）

```python

LAMDA          = 0.95     # GAE λ
CLIP_PARAM     = 0.2      # PPO ε
DUAL_CLIP_C    = 3.0      # dual-clip lower bound（仅 adv<0 时生效）

LSTM_HIDDEN    = 512      # baseline 已经是这个
LSTM_TIMESTEPS = 16       # baseline 已经是这个
```

**Dual-clip PPO 的正确实现**（替换 baseline 的 `model.py:219`）：

```python
ratio = torch.exp(log_pi - log_pi_old)
surr1 = ratio * advantage
surr2 = torch.clamp(ratio, 1 - clip_eps, 1 + clip_eps) * advantage
clip1 = torch.min(surr1, surr2)
# 仅当 advantage < 0 时再加一层下界
clip2 = torch.max(clip1, dual_clip_c * advantage)  
policy_loss = -torch.where(advantage < 0, clip2, clip1).mean()
```

**Advantage 归一化（baseline 没有，必加）**：

```python
adv = (adv - adv.mean()) / (adv.std() + 1e-8)
```

**Value clipping（防止 critic 跳跃）**：

```python
v_clipped = v_old + torch.clamp(v_new - v_old, -clip_eps, clip_eps)
v_loss = 0.5 * torch.max((v_new - target)**2, (v_clipped - target)**2).mean()
```

### 4.6 Self-play 课程

赛题环境支持三种对手：`common_ai`（规则 AI，水平固定）、`selfplay`（自对弈）、`{model_id}`（指定模型）。

**三阶段课程**（参考 AlphaStar 的 [PFSP](https://storage.googleapis.com/deepmind-media/research/alphastar/AlphaStar_unformatted.pdf) 简化版）：

1. **预热（前 ~6 小时）**：`opponent_agent="common_ai"`，让模型先学会基本走位、补刀、攻击塔；evaluation 用 common_ai。胜率达到 80% 以上后切换。
2. **自对弈（中段，~48-72 小时）**：`opponent_agent="selfplay"`。维护一个 opponent pool：每 `dump_model_freq*N` 步存一个 checkpoint 进池子，训练时按"最新模型 70% + 历史随机 20% + 最弱 10%"采样。`kaiwu.json` 里挂 3 个不同强度的 model_id 做评估。
3. **PFSP 阶段（末段）**：根据评估胜率，**多对自己赢不了的历史模型采样**（`p ∝ (1 - winrate(self, opponent))^2`），逼模型补短板。

**实施要点**：
- baseline 的 `workflow/train_workflow.py:283-301` 已经预留了对手模型加载的 if 分支，把"random model from pool"实现成 PFSP 采样即可。
- 训练时打开 `auto_switch_monitor_side=true`（baseline 默认开），让红蓝两侧轮流被监控，避免单边偏置。

### 4.9 实战增量：来自电子科大亚军（第二届开悟 + 大运会冠军）的具体 trick

> 本节内容整理自 [腾讯多智能体强化学习大赛冠军思路分享（清水河畔混分王 / 电子科大）](https://zhuanlan.zhihu.com/p/654972230)。该文章作者参加的是 3v3 长平攻坚战赛题，但**绝大部分技术对 1v1 同样适用**，且给出了非常具体的数值与公式。这是其它公开资料里找不到的实战经验，价值极高。

#### 4.9.1 战略层级的认知（最重要）

> "第一届很多队伍尝试各种 RL 算法，最终冠军全是 PPO；第二届所有队伍都不再纠结，无一例外用 PPO。此时大家开始卷损失函数设计、网络模型设计、奖励函数设计。"

> "我们队伍明确了具体的战略目标：先提高单智能体水平，然后全力卷多智能体合作对抗 ……我们的团战水平高于清华，而单智能体水平低于清华。"

对 1v1 的迁移：1v1 没有团队合作维度，单智能体水平就是一切。**所有精力放在网络结构 / 奖励 / Self-play 课程**。

> "训练资源有限"——他们只有 1024 cores + 1 GPU，**很多论文里的 trick（如 OpenAI Five 的大 teamspirit、4096 维 LSTM）在小算力下完全没用甚至有害。**

对 1v1 的迁移：开悟 1v1 的训练资源同样受限，**别盲目抄绝悟论文的网络规模**——下面 4.9.4 的 FC+GRU 混合是更合适的选择。

#### 4.9.2 动作约束损失（Action Constraint Loss）—— 训 1 小时即可完全消除"站桩 / 乱放技能"

**核心认知**：英雄会陷入 "no action" 状态站着不动、乱放惩戒/恢复技能等，是因为这些"坏行为"无法直接通过 reward 表达。**通过给 policy logits 加一个独立的 L2 损失项可以间接实现**：

$$\mathcal{L}_{action}=\sum_{j=1}^{batch}\sum_{i=1}^{n}\bigl(A_{ij}\cdot \mathrm{Mask}_{i}\bigr)^2$$

其中：
- $A_{ij}$ 是 batch 里第 j 个样本对第 i 个动作的概率（softmax 输出）
- $\mathrm{Mask}_{i}$ 是 0/1 向量：希望抑制的动作设为 1

**作用机制**：等价于在 policy loss 上叠加了一个隐式的"减分"，相当于给指定动作设置了一个软性负 reward。
**实测效果**：作者原话："只需要 1 个小时的训练就能完全规避站着不动的问题，并且还可以对这个 loss 设置具体的权重因子，比如对技能释放的惩罚。我们通过这种方式实现了惩戒的精准释放，打野的惩戒捏的非常紧。"

**对 1v1 的具体落地**（`agent_diy/algorithm/algorithm.py` 在 `learn` 里加几行）：

```python
# 在 PPO loss 计算后添加
# 1) 抑制 button=NONE（baseline 的 NONE_ACTION = [0, 15, 15, 15, 15, 0]，0 就是 NONE）
button_probs = label_probability_list[0]   # [B, 12]
button_mask = torch.zeros(12, device=device)
button_mask[0] = 1.0   # NONE 位
loss_action_no_op = ((button_probs * button_mask) ** 2).sum(dim=1).mean()

# 2) 抑制 button=Recall（回城，索引 9，普通对线时不应该回城）
# 只在血量充足时抑制；血量低时不要抑制
recall_mask = torch.zeros(12, device=device)
recall_mask[9] = 1.0
hp_high_mask = (hp_rate > 0.7).float()    # [B]
loss_action_no_recall = ((button_probs * recall_mask) ** 2 * hp_high_mask.unsqueeze(1)).sum(dim=1).mean()

# 总 loss
self.loss = self.value_cost + self.policy_cost + self.var_beta * self.entropy_cost \
            + 0.5 * loss_action_no_op + 0.3 * loss_action_no_recall
```

可以扩展抑制：满血时不要用治疗术、敌方塔附近不要无视塔输出、CD 时不要点亮技能键等。**这是把人类先验注入 RL 最干净的方法之一**，比改 reward 有效得多。

#### 4.9.3 情景奖励（Scenario Reward）—— 让稀有但关键的样本不被淹没

**核心认知**：训练资源有限时，关键的"对线博弈样本"（比如击杀、推塔、关键技能命中）在样本池里占比极低，会被大量"普通走位样本"淹没。**通过对特定情景设置非常大（甚至离谱大）的奖励，相当于借助 GAE 的 γ 反向传播来"扩增高价值样本"**。

> "比如击杀暴君，可能一整局里只有几帧的有效样本，而一整局的样本数一般都上千，有效样本容易淹没在池子里。所以即使击杀暴君是稀疏奖励，可以有意识地给他设置一个比较大甚至有些许离谱的奖励值。"

**3v3 里他们用的情景例子**："当我方有英雄被击杀时，如果前后 2s 时间内我方其他英雄不在忙的状态（攻击地方或者推塔），则给予其他英雄一个较大惩罚"——单这一个情景，模型直接提升 2 个 baseline 水平。

**对 1v1 的具体落地**（`agent_ppo/feature/reward_process.py` 在 `get_reward` 里追加）：

```python
# 情景 1：在敌塔范围内成功命中敌方英雄一次（同时不被塔反伤）→ 大正奖励
if main_hero_hit_enemy_in_tower_range and not tower_hit_main_hero:
    reward_dict["scenario_pressure_dive"] = +5.0

# 情景 2：技能命中敌方英雄关键技能（如鲁班大、狄仁杰大）→ 大正奖励
if ult_skill_hit_enemy:
    reward_dict["scenario_ult_hit"] = +3.0

# 情景 3：自身血量低于 30% 仍主动靠近敌方 → 大负奖励（鼓励残血撤退）
if main_hero_hp_rate < 0.3 and dist_to_enemy < safe_dist:
    reward_dict["scenario_low_hp_engage"] = -3.0

# 情景 4：连续 N 帧 button=NONE → 累积负奖励（与动作约束损失互补）
if no_op_streak > 5:
    reward_dict["scenario_idle"] = -0.5

# 情景 5：在敌方塔即将被推掉时（HP < 20%）撤退或站桩 → 大负奖励
if enemy_tower_hp_rate < 0.2 and main_hero_not_attacking_tower:
    reward_dict["scenario_miss_finish"] = -2.0
```

**关键原则**：奖励值要"夸张地大"（比常规 dense reward 大 1-2 个数量级），目的不是让数值合理，而是让 GAE 反传到上游 50-100 帧的样本时仍有足够梯度信号。这是把稀疏样本"密集化"的取巧做法。

#### 4.9.4 网络结构具体参数（来自实战）

> "对于只有 1024 个 core 的我们而言，大维度的 LSTM 是很容易过拟合的。"

**FC + GRU 混合结构（FC : LSTM = 3 : 1，concat）**——该作者实测有效，且**清华队伍独立得出了相同的比例**：

```python
# 假设融合后的特征是 1024 维
fc_branch = MLP(1024, [768, 768, 768])   # 3 份 FC
gru_branch = nn.GRU(1024, 256, batch_first=True)  # 1 份 GRU（256 维 → 是 LSTM 的 1/3）
features = torch.cat([fc_out, gru_out], dim=-1)  # 768 + 256 = 1024
```

baseline 现在是 LSTM_UNIT_SIZE=512 全 LSTM，**改成 FC 768 + GRU 256 这个比例**，过拟合风险显著下降，且 GRU 比 LSTM 参数更少、训练更快。

**PSCN（Power Series Connected Neural Network，作者自创）**——类残差结构，在保证宽度和深度的前提下减少参数冗余：

```python
# 简化伪代码（原文没有给完整公式，按描述推测：每层只对前一层的子集做扩展）
class PSCN(nn.Module):
    def __init__(self, dim, depth=3):
        super().__init__()
        # 每层只处理输入的一半，另一半直通
        self.layers = nn.ModuleList([
            nn.Linear(dim // 2, dim // 2) for _ in range(depth)
        ])
    def forward(self, x):
        a, b = x.chunk(2, dim=-1)
        for layer in self.layers:
            a = F.relu(layer(a)) + a   # 残差
        return torch.cat([a, b], dim=-1)
```

**网络规模**：作者最终模型大小约 50 MB（"我们当时网络有点大"）——这是上限警戒线，不要超过。

**Target-first concat**——"先决定打谁，再决定怎么打"：作者透露（图中没画出）他们在 forward 里 **先用 attention 算出 target，再把 target embedding concat 回主特征向量**，再算 action 和 value。这比把 target 作为独立 head 多一步，但实测效果更好。

```python
# 伪代码
target_logits = target_attention(lstm_out, unit_embeddings)
target_id = target_logits.argmax(dim=-1)
target_embed = unit_embeddings[target_id]
final_feature = torch.cat([lstm_out, target_embed], dim=-1)
button_logits = button_head(final_feature)
move_logits = move_head(final_feature)
value = value_head(final_feature)
```

#### 4.9.7 Self-play 评分机制（OpenAI Five 风格）

> "腾讯提供的 baseline 是 naive self-play，每次选择博弈有 30% 等概率选择历史模型池中的模型进行博弈。大家其实可以换成 OpenAI Five 中提到的评分机制 …… 在后续训练中，模型能力退化现象有所好转。"

**实施方法**：
- 给每个 checkpoint 维护一个 Elo 分数（每次对战后用经典公式更新）
- 采样时按概率 `p ∝ exp(Elo / T)`，T 是温度参数
- **把训练过程中最强的 3-5 个 checkpoint 永久固定在池子里**（"祖传强模型"），防止能力退化

#### 4.9.8 Module Soup（模型融合）—— 比赛冲刺阶段必做

> "如果你训练了多种不同风格的模型，可以对每个模型进行加权融合，这种做法可以增强模型的鲁棒性 …… 融合至少不掉点。"

**实施**：训练 3-5 个风格不同的 checkpoint（不同 reward 权重 / 不同 self-play 策略），最后一周直接 **state_dict 加权平均**：

```python
def soup(state_dicts, weights):
    avg = {}
    for k in state_dicts[0]:
        avg[k] = sum(w * sd[k] for w, sd in zip(weights, state_dicts)) / sum(weights)
    return avg

soup_model = soup([ckpt_aggressive, ckpt_defensive, ckpt_balanced], [1.0, 1.0, 1.5])
```

实测在 ImageNet / MOBA 上都不掉点，且鲁棒性更强。

> "笔者当初把貂蝉的特征提取网络接到了李元芳的决策网络中，导致李元芳通过貂蝉的特征进行决策，这件事情在最后的 code review 过程中才被发现 …… 最后差了清华 4 分，直接损失 10w 奖金。"

## 6. 风险点与对策

| 风险 | 触发信号 | 对策 |
|----|----|----|
| **Reward hacking**：模型学会"卡视野"或者"只补刀不打架" | 胜率涨但 kill 数极低或者塔血变化慢 | 加 attack_hero reward；把 forward 权重再调高一点；用 4.9.2 的动作约束损失抑制 NONE |
| **PPO 训崩**：value_loss 爆炸、entropy 跌到 0 | TB 上 value_loss 跳 10x、policy entropy < 0.5 | lr 下调一半，clip 改 0.1，gradient clip 改 0.3 |
| **Self-play 陷入对称纳什**：双方都保守不打 | 对局帧数长期在 18000+，胜率震荡在 50% | 引入 main exploiter；reward 加正向 forward；引入"残血进塔"的情景奖励 |
| **过拟合到自身风格**：vs selfplay 强但 vs common_ai 反而退步 | eval winrate vs common_ai 下降 | 对手池里固定保留 common_ai 占 10% 采样；用 4.9.7 把强 checkpoint 永久 pin 住 |
| **平台资源限制**：模型保存达到 400 次上限 | 报错 | `dump_model_freq` 至少 ≥ 训练总步数 / 380 |
| **梯度同步延迟**：actor 和 learner 模型版本差太大导致 dual-clip 频繁触发 | 监控里 ratio 直方图大量 > 3 的样本 | 减小 `model_file_sync_per_minutes`；或者把 c 改成 5 |
| **召唤师技能策略表偏置**：某种技能从来没被采样 | 4×10 表里大量 0 | 加 ε-greedy 兜底，ε=0.1 |
| **网络过拟合（小算力 + 大 LSTM）** | 训练胜率高但 eval 胜率低、训练 reward 远高于 eval reward | 改用 4.9.4 的 FC:GRU=3:1 混合；GRU 维度从 512 降到 256 |
| **特征→head 接错（致命）**：比如蓝方红方共享同一个 normalizer 但镜像变换写漏 | hero_camp 维度的胜率严重不对称（一边 70%、另一边 30%） | 4.9.9 提到的灾难型 bug，每周必须 code review；写单元测试模拟左/右两侧的 observation，断言模型输出对称 |
| **课程奖励切换震荡**：从 EARLY 切到 MID 时模型退化 | 切换后 reward 跳水、胜率下降 5%+ | 用 PopArt（4.5）做奖励归一化；切换时 lr 临时下调 50% 渡过 |
