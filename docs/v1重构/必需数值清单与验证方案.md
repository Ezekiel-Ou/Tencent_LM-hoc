## 三、关键发现：运行时字段值

**重要**：虽然协议没有给出固定数值，但**每个单位在运行时都有这些字段的当前值**：

```python
# 从 frame_state.hero_states[0] 可以读取到：
{
    "attack_range": 12000,  # 当前英雄的普攻范围
    "sight_area": 5000,     # 当前英雄的视野半径
    "location": {"x": 1234, "y": 0, "z": -5678},  # 当前位置
    "hp": 8000,
    "max_hp": 12000,
    # ...
}
```

这意味着：
1. **普攻范围**和**视野范围**可以从每个英雄的属性中**动态读取**
2. **地图范围**可以通过追踪所有单位的坐标**极值**来确定

## 四、最小验证方案

由于不需要知道绝对精确的数值，我们只需要验证**相对关系**，以下是**最小化验证方案**：

### 验证1：地图坐标范围（决定全局编码）

```python
# 在 feature_process.py 中添加临时日志
max_x, max_z = 0, 0
min_x, min_z = 0, 0

for unit in heroes + npcs:
    loc = unit.get("location", {})
    x, z = loc.get("x", 0), loc.get("z", 0)
    max_x, max_z = max(max_x, x), max(max_z, z)
    min_x, min_z = min(min_x, x), min(min_z, z)

self.logger.info(f"MAP_RANGE: x=[{min_x}, {max_x}], z=[{min_z}, {max_z}]")
```

**预期输出**：
- 如果 `max_x ≈ 12000~15000` → hok_semi的±12300假设合理
- 如果 `max_x ≈ 20000+` → 需要扩大编码范围

### 验证2：视野断开距离（决定相对编码范围）

```python
# 记录敌方英雄可见时的最大距离
if enemy_hero_visible:
    dist = distance(self_pos, enemy_pos)
    self.logger.info(f"SIGHT_MAX_DIST: {dist}")
```

**预期输出**：
- 当敌方从可见变为不可见时，记录此时的距离
- 这个距离 ≈ 视野半径

### 验证3：普攻范围（验证攻击距离）

```python
# 当 attack_target 非空时，记录距离
if hero.get("attack_target"):
    target = find_target(hero.get("attack_target"))
    dist = distance(self_pos, target_pos)
    attack_range = hero.get("attack_range", 0)
    self.logger.info(f"ATTACK: dist={dist}, attack_range={attack_range}")
```

**预期输出**：
- `dist` 应该 ≤ `attack_range`
- 这验证了我们的距离计算是正确的

## 六、务实的方案

如果确认本次赛题和hok_semi使用的是**完全相同的墨家机关道地图**：

**风险**：如果地图有微调（如出生点位置变化），位置编码可能需要调整。

### 方案B：运行时自适应（更稳健）

修改代码，让位置编码**根据实际坐标范围自适应**：

```python
class FeatureProcess:
    def __init__(self, ...):
        # 运行时统计
        self.observed_max_coord = 0
        self.observed_max_dist = 0
    
    def process_feature(self, observation):
        # ... 原有代码 ...
        
        # 更新观测到的坐标范围
        for unit in heroes + npcs:
            loc = unit.get("location", {})
            x, z = abs(loc.get("x", 0)), abs(loc.get("z", 0))
            self.observed_max_coord = max(self.observed_max_coord, x, z)
        
        # 如果超出编码范围，发出警告
        if self.observed_max_coord > RELATIVE_DISTANCE_MAX_SIZE / 2:
            self.logger.warning(
                f"Coordinate {self.observed_max_coord} exceeds "
                f"encoding range {RELATIVE_DISTANCE_MAX_SIZE/2}"
            )
```

## 七、必须验证 vs 可以假设

| 参数 | 是否可以假设hok_semi正确 | 验证方法 | 不验证的风险 |
|------|------------------------|---------|-------------|
| 地图坐标范围 | ⚠️ 建议验证 | 打印最大坐标 | 位置编码溢出，模型看到全0 |
| 视野范围 | ⚠️ 建议验证 | 观察敌方消失时的距离 | 视野外目标编码错误 |
| 600网格大小 | ✅ 可以假设 | 无需验证 | 精度略微偏差，影响较小 |
| 5000网格大小 | ✅ 可以假设 | 无需验证 | 精度略微偏差，影响较小 |
| 特征维度 | ✅ 可以假设 | `assert len(feature) == 3910` | 模型输入维度不匹配，直接崩溃 |
| HP/EP/CD范围 | ✅ 可以假设 | 观察最大值是否在范围内 | 离散化bucket不够，信息丢失 |

## 八、建议的验证顺序

```
Step 1: 运行 python train_test.py（如果可用）
    ├── 如果能运行 → 看日志中的坐标范围
    └── 如果不能 → 需要配置环境

Step 2: 在 feature_process.py 中添加临时日志
    ├── 打印每100帧的最大坐标
    ├── 打印敌方可见时的最大距离
    └── 运行1-2局收集数据

Step 3: 分析日志
    ├── max_coord ≈ 12000~15000 → ✅ 假设正确
    ├── max_coord ≈ 8000~10000 → ⚠️ 范围偏小，可能不需要调整
    └── max_coord > 20000 → 🔴 需要扩大编码范围

Step 4: 根据结果决定
    ├── 如果匹配 → 直接使用hok_semi参数
    └── 如果不匹配 → 调整RELATIVE_DISTANCE_MAX_SIZE等参数
```

## 结论

**核心问题**：官方协议只提供了字段名，没有提供数值常量。

**解决方案**：
1. **大部分参数可以信任hok_semi**（如果地图相同）
2. **关键参数需要运行时验证**（地图范围、视野范围）
3. **验证成本低**：只需添加几行日志，运行1-2局游戏

**最务实的做法**：先假设hok_semi的参数正确，启动训练，同时监控日志中的坐标范围。如果发现有溢出警告（坐标超出编码范围），再调整参数。**不要过度设计验证流程，先让代码跑起来**。
